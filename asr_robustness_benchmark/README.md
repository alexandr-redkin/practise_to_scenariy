
# Kazakh-Russian Medical Speech ASR Robustness Benchmark

Исследовательский программный прототип к статье **«Исследование устойчивости систем распознавания казахско-русской медицинской речи к аудиоподделкам»**.

Проект продолжает подготовительный анализ Google FLEURS (`kk_kz`, `ru_ru`) и реализует воспроизводимый базовый эксперимент: сравнение двух многоязычных ASR-моделей на исходном аудио и на аудио с контролируемыми преобразованиями сигнала.

> **Важное ограничение интерпретации.** Добавление шума, изменение усиления, полосы частот и повторная дискретизация — это контролируемые акустические воздействия для первичной оценки устойчивости ASR. Они **не являются полноценной генерацией deepfake/voice conversion** и не доказывают способность системы обнаруживать поддельную речь. Для такого вывода потребуются отдельные наборы поддельных аудио и модели обнаружения spoofing.

## 1. Связь с научной статьёй

| Материал статьи | Реализация в проекте |
|---|---|
| FLEURS `kk_kz` и `ru_ru` | Загрузка тестовых выборок двух языков |
| Поля `audio`, `transcription`, `language` | Используются как входной сигнал, эталон и языковая метка |
| Медицинский словарь | `data/glossary/medical_terms.json` |
| Потенциальные ошибки терминологии | Метрика MTRA при наличии терминов в эталонном тексте |
| WER и CER | Расчёт для каждой модели и каждого типа аудио |
| Ограничения корпуса | В отчёте отдельно учитывается, что FLEURS содержит общую, а не медицинскую речь |

## 2. Возможности

- Два многоязычных ASR-бейзлайна: Whisper Small и Whisper Medium.
- Два языка: казахский и русский.
- Условия: `clean`, `noise`, `volume`, `bandlimit`, `resample`.
- Метрики: WER, CER, MTRA и изменение WER относительно исходной записи.
- Экспорт подробных результатов и агрегированной таблицы в CSV.
- Сохранение обработанных аудиофайлов по желанию.
- Unit-тесты для преобразований аудио и метрик.

Модели по умолчанию:
- `openai/whisper-small`
- `openai/whisper-medium`

Для запуска Medium потребуется больше оперативной/видеопамяти. При ограниченных ресурсах можно заменить её другой совместимой многоязычной Whisper-моделью через параметр командной строки.

## 3. Запуск в Google Colab

### Шаг 1. Установка

```bash
!git clone https://github.com/YOUR_USERNAME/asr-robustness-benchmark.git
%cd asr-robustness-benchmark
!pip install -r requirements.txt\n!pip install -e .
```

### Шаг 2. Запуск небольшого пилотного эксперимента

```bash
!python -m asr_benchmark.cli \
  --languages kk_kz ru_ru \
  --samples-per-language 10 \
  --models openai/whisper-small openai/whisper-medium \
  --output results
```

Для первичной проверки лучше начать с 5–10 записей на язык. После проверки среды можно увеличить выборку. Полный тест на всех 1 631 записях может потребовать значительного времени и вычислительных ресурсов.

### Шаг 3. Запуск на большем количестве записей

```bash
!python -m asr_benchmark.cli \
  --languages kk_kz ru_ru \
  --samples-per-language 100 \
  --models openai/whisper-small openai/whisper-medium \
  --output results
```

Параметр `--samples-per-language 0` означает использование всей тестовой выборки. Не запускайте полный объём до успешного пилотного теста.

## 4. Что формируется

В папке `results/` появятся:

- `predictions.csv` — подробные результаты по каждой записи, модели и условию;
- `summary.csv` — агрегированные WER, CER, MTRA и изменение WER;
- `run_metadata.json` — параметры запуска и версии основных библиотек.

В `predictions.csv`:
- `language` — языковая конфигурация FLEURS;
- `sample_id` — идентификатор записи;
- `model` — использованная ASR-модель;
- `condition` — тип аудиовоздействия;
- `reference` — эталонная транскрипция;
- `hypothesis` — результат ASR;
- `wer`, `cer` — ошибки распознавания;
- `mtra` — точность распознавания медицинских терминов, если в эталоне присутствует хотя бы один термин словаря.

Если в тестовом тексте нет терминов из медицинского словаря, MTRA записывается как `NaN`, а не как 0. Это важно: отсутствие медицинских терминов в общей речи FLEURS не означает нулевую точность медицинского распознавания.

## 5. Медицинский словарь

Файл `data/glossary/medical_terms.json` содержит примеры терминов из статьи. Для MTRA учитываются точные нормализованные вхождения. В дальнейшем словарь можно расширить казахскими эквивалентами, вариантами написания и произношения.

**Важно:** поскольку исходный FLEURS — корпус общей речи, MTRA может быть недоступен для части или всех тестовых записей. Для полноценной оценки MTRA следует отдельно подготовить медицинские диктовки с эталонными транскрипциями.

## 6. Методика и интерпретация

Для каждого аудиофайла создаются варианты:
- `clean` — исходный сигнал;
- `noise` — добавление слабого гауссовского шума;
- `volume` — изменение амплитуды;
- `bandlimit` — ограничение полосы частот;
- `resample` — имитация ухудшения качества за счёт понижения частоты дискретизации и возврата к исходной частоте.

Сравниваются WER/CER для исходной записи и преобразованных вариантов. `wer_delta` показывает разницу между WER преобразованного и чистого сигнала: положительное значение означает ухудшение.

Эти преобразования — воспроизводимые стресс-тесты акустической устойчивости, но не замена испытаниям на TTS, voice conversion, replay и adversarial audio.

## 7. Воспроизводимость и ограничения

- В статье указано 8 118 записей в двух конфигурациях и 1 631 тестовая запись суммарно.
- Код использует только тестовые части `kk_kz` и `ru_ru`, чтобы не обучать модели на тестовых примерах.
- Результаты зависят от версии моделей, библиотек, оборудования и параметров преобразования.
- Whisper Medium может быть слишком тяжёлой для бесплатной среды Colab.
- Перед публикацией результатов укажите дату запуска, версии библиотек, модели, количество записей и фактические параметры эксперимента.
- Не представляйте демонстрационный запуск на 10 записях как результат полного исследования.

## 9. Научная формулировка практической части

«В качестве практического продолжения анализа экспериментальной базы реализован программный прототип для сравнительной оценки устойчивости многоязычных систем автоматического распознавания речи. Прототип обеспечивает загрузку тестовых аудиозаписей казахской и русской конфигураций корпуса Google FLEURS, формирование контролируемых вариантов входного сигнала, распознавание с использованием двух ASR-моделей и расчёт метрик WER, CER и MTRA. Полученные показатели позволяют оценить изменение качества транскрибирования при акустических воздействиях. При этом используемые преобразования рассматриваются как базовые стресс-тесты устойчивости и не интерпретируются как полноценная генерация или обнаружение аудиоподделок».
